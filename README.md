# Tbonk Tasks — практикум по эксплуатации приложения

Трекер задач на Flask + PostgreSQL. Браузерный интерфейс и API работают в одном приложении.

```bash
cp .env.example .env
docker compose up --build
```

Открыть http://localhost:8000. Проверка БД: `/health`.

Kubernetes: `bash scripts/deploy-app.sh` после сборки и загрузки образа по инструкции ДЗ‑2.

## Структура проекта

- `backend/` — Flask API, запуск Gunicorn, административные команды, зависимости и тесты Python.
- `frontend/` — HTML, CSS и JavaScript; Flask отдаёт эти файлы вместе с API.
- `k8s/`, `scripts/`, Dockerfile и Compose — сборка и развёртывание приложения.
- `docs/` — объяснения и отчёты по домашним заданиям.

Команды выполняются из корня проекта. Создание схемы вручную: `python -m backend.manage init-db` (нужны зависимости и настройки PostgreSQL). Зависимости: `python -m pip install -r backend/requirements.txt`; тесты: `python -m pytest`. При запуске через Compose или Kubernetes схема создаётся автоматически отдельным процессом.

Для каждой домашки используется одна ветка: `hw_1`–`hw_6`. Все доработки и исправления коммитятся и отправляются прямо в ветку соответствующей домашки. В `hw_1` уже включены исправления замечаний. Домашки образуют последовательную цепочку; для просмотра изменений сравнивайте текущую ветку с предыдущей. Новые коммиты в предыдущей домашке не появляются в следующих автоматически: при необходимости их переносят отдельно.

[Фактические проверки, скриншоты и запуск сохранённого стенда](docs/Проверка.md).

Начать изучение стоит с объяснения ДЗ‑1: там разобран путь запроса от кнопки в браузере до транзакции PostgreSQL и дана карта исходных файлов. Затем читать домашки по порядку: контейнер → Kubernetes → логи → метрики → цели качества → алерты.

```bash
git diff hw_1...hw_2
git diff hw_2...hw_3
git diff hw_3...hw_4
git diff hw_4...hw_5
git diff hw_5...hw_6
```

Тесты полного API используют PostgreSQL и очищают тестовую таблицу. Не запускайте их на БД с ценными данными.
