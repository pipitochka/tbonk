## Сохранённый стенд на этой машине

Рабочая копия: `/Users/artem-akulov/Study/Tbonk/tbonkl-homework`.

Инструменты и состояние кластера: `/Users/artem-akulov/Study/Tbonk/tbonkl-lab`. Они находятся вне Git: сертификаты и локальный kubeconfig не должны попадать в репозиторий. Глобальный kubeconfig и shell rc не изменены.

```bash
source /Users/artem-akulov/Study/Tbonk/tbonkl-lab/env.sh
cd /Users/artem-akulov/Study/Tbonk/tbonkl-homework
minikube -p tbonk-homework status
kubectl --context tbonk-homework get pods -A
```

Используется установленный Podman, а не Docker Desktop: Kubernetes 1.34.1, minikube 1.39.0, CRI-O, один узел 4 CPU / 6 GiB. Локальная команда `docker` на этой машине ссылается на Podman. Полные инструкции обычного Docker-варианта приведены в ДЗ‑2.

После перезагрузки сначала запустить Podman VM и кластер:

```bash
podman machine start podman-machine-default
minikube start -p tbonk-homework --driver=podman --rootless=false \
  --container-runtime=cri-o --kubernetes-version=v1.34.1 --cpus=4 --memory=6144
```

Если VM уже работает, повторный start не нужен. Для доступа каждый port-forward запускается в отдельном терминале:

```bash
kubectl --context tbonk-homework -n tbonk port-forward svc/tbonk 8000:8000
kubectl --context tbonk-homework -n monitoring port-forward svc/victorialogs 9428:9428
kubectl --context tbonk-homework -n monitoring port-forward svc/vm-single 8428:8428
kubectl --context tbonk-homework -n monitoring port-forward svc/alert-inbox 8088:8080
```

Приложение: `http://localhost:8000/`. Логи: `http://localhost:9428/select/vmui/`. Метрики: `http://localhost:8428/vmui/`. Уведомления: `http://localhost:8088/`. При занятом порте поменять только левое число. После rollout port-forward приложения может потребовать перезапуска.

Чтобы освободить ресурсы ноутбука, использовать `minikube stop -p tbonk-homework`; данные остаются. `minikube delete` удалит кластер и его учебные PVC, поэтому для обычной остановки не нужен.
